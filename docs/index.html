How the search works

A request is a standing instruction, not a one-off query. Once created, the search service works through the brand checklist in Config/brands.json — 26 manufacturer groups, 136 brands — one brand at a time, and commits results back to this repository as it goes. You can close the page; progress is kept in the request itself.

Per brand

  1. Model discovery. Find the models that brand sells which match your body type, model-year floor and special filter. The filters go into the search query, so nothing is researched only to be thrown away afterwards.
  2. Specifications. Read the manufacturer’s own pages for engine, consumption, tank or battery size, doors, roof mechanism and a photo.
  3. Real offerings. At least ten rounds per model against Portuguese classifieds first, then EU-wide ones. Each round is steered somewhere the previous rounds did not look, and excludes everything already found.
  4. Budget. Averaged from the real prices found. No offerings means no average — not an estimate dressed up as one.

What it will not do

Every listing here is a page a browser actually opened, at a price that was actually printed on it, in the EU or EEA. A model with nothing for sale is recorded as having nothing for sale. An honest “none found” always beats an invented listing, so the offering counts are sometimes lower than you might expect — that is the point.

Sync favorites to GitHub

Commits Requests/<request>/favorites.json straight to Maksym-Denysiuk/CarsSearch on every star click, calling GitHub's REST API directly from this page — no backend involved. Needs a token scoped to this repository only.

  1. Create a fine-grained personal access token.
  2. Resource owner Maksym-Denysiuk, repository access → only select repositories → CarsSearch.
  3. Permissions → Repository permissions → Contents: Read and write. Nothing else.
  4. Paste the token below. It is stored only in this browser's local storage and sent only to api.github.com.
